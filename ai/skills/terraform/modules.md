# Terraform Module Pattern

## When to use

- Reusable infrastructure components
- Standardized deployments

## Structure

- variables.tf
- main.tf
- outputs.tf

## Best practices

- Avoid hardcoding values
- Use variables for all external inputs
- Keep modules focused (single responsibility)
- Use naming conventions
- Expose enable flags, environment-aware defaults, retention controls, and
  naming customization when they materially affect cost or destroyability
- Design modules so `terraform apply`, `terraform destroy`, and a subsequent
  `terraform apply` work without manual cleanup
- Declare supporting infrastructure explicitly in Terraform modules when it is
  part of the intended service behavior, including logging resources, instead
  of depending on autogenerated service-side defaults

## Example use cases

- S3 bucket module
- IAM role module
- Glue job module

## Common mistakes

- Over-generalization
- Tight coupling between modules
- Orphan resources that require manual cleanup outside Terraform
