# File Upload UX Pattern

## When to use

- Implementing the invoice upload flow in `UploadPage`
- Adding drag-and-drop or multi-file upload to any frontend component
- Wiring browser-side uploads to S3 via presigned URLs

## Core idea

The browser uploads directly to S3 using a presigned URL generated by the
backend. The Lambda is not in the upload data path. This is required for files
larger than the API Gateway 10 MB payload limit and is the correct pattern for
all document uploads regardless of file size.

---

## Presigned URL upload flow

```
User selects file
  → validate file (type, size)
  → POST /upload/presign  { filename, content_type }
  → Lambda validates auth + generates presigned PUT URL
  → PUT <presigned_url>  (browser → S3 directly)
  → S3 fires ObjectCreated event → pipeline starts
  → frontend polls GET /documents/{id}/status
```

The frontend never knows the pipeline has started from the upload response —
it polls a separate status endpoint.

## File validation (before requesting presigned URL)

Validate before making any API call to avoid wasted requests:

```javascript
const ALLOWED_MIME_TYPES = ['application/pdf', 'image/tiff', 'image/jpeg', 'image/png']
const MAX_FILE_SIZE_BYTES = 200 * 1024 * 1024  // 200 MB hard limit
const WARN_FILE_SIZE_BYTES = 50 * 1024 * 1024  // 50 MB warning

function validateFile(file) {
  if (!ALLOWED_MIME_TYPES.includes(file.type)) {
    return { valid: false, error: `Unsupported file type: ${file.type}` }
  }
  if (file.size > MAX_FILE_SIZE_BYTES) {
    return { valid: false, error: `File too large: ${(file.size / 1e6).toFixed(1)} MB (max 200 MB)` }
  }
  return { valid: true, warning: file.size > WARN_FILE_SIZE_BYTES ? 'Large file — upload may take a moment' : null }
}
```

Also check the `accept` attribute on the `<input>` element as a first line of
defence, but always re-validate in JavaScript because `accept` can be bypassed.

## Upload with progress tracking

Fetch API does not expose upload progress. Use `XMLHttpRequest`:

```javascript
function uploadToS3(presignedUrl, file, onProgress) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest()

    xhr.upload.onprogress = (event) => {
      if (event.lengthComputable) {
        onProgress(Math.round((event.loaded / event.total) * 100))
      }
    }

    xhr.onload = () => {
      if (xhr.status >= 200 && xhr.status < 300) resolve()
      else reject(new Error(`S3 upload failed: ${xhr.status}`))
    }

    xhr.onerror = () => reject(new Error('Network error during upload'))

    xhr.open('PUT', presignedUrl)
    xhr.setRequestHeader('Content-Type', file.type)
    xhr.send(file)
  })
}
```

## Multi-file queue

Track each file's state independently. Process files with a concurrency limit
to avoid S3 throttling:

```javascript
// State shape for each file in the queue
// { id, file, status: 'pending'|'validating'|'uploading'|'done'|'error', progress, error }

const MAX_CONCURRENT_UPLOADS = 3

async function uploadQueue(files, requestPresignedUrl) {
  const queue = [...files]
  const active = []

  async function processNext() {
    if (queue.length === 0) return
    const item = queue.shift()
    const task = uploadFile(item, requestPresignedUrl).finally(() => {
      active.splice(active.indexOf(task), 1)
      processNext()
    })
    active.push(task)
  }

  for (let i = 0; i < Math.min(MAX_CONCURRENT_UPLOADS, files.length); i++) {
    processNext()
  }

  await Promise.allSettled(active)
}
```

## Drag-and-drop with input fallback

Always provide both interaction paths and test both explicitly:

```jsx
function DropZone({ onFiles }) {
  const inputRef = useRef()

  function handleDrop(e) {
    e.preventDefault()
    onFiles([...e.dataTransfer.files])
  }

  return (
    <div
      onDragOver={(e) => e.preventDefault()}
      onDrop={handleDrop}
      onClick={() => inputRef.current.click()}
    >
      <p>Drop files here or click to select</p>
      <input
        ref={inputRef}
        type="file"
        multiple
        accept=".pdf,.tif,.tiff,.jpg,.jpeg,.png"
        style={{ display: 'none' }}
        onChange={(e) => onFiles([...e.target.files])}
      />
    </div>
  )
}
```

## Pipeline status polling

S3 `ObjectCreated` triggers the pipeline asynchronously. The upload response
does not mean processing is complete. Poll the status endpoint:

```javascript
async function pollStatus(documentId, interval = 3000, timeout = 300000) {
  const deadline = Date.now() + timeout
  while (Date.now() < deadline) {
    const { status } = await client.get(`/documents/${documentId}/status`).then(r => r.data)
    if (status === 'completed' || status === 'failed') return status
    await new Promise(r => setTimeout(r, interval))
  }
  throw new Error('Status polling timed out')
}
```

Show a "Processing…" state between upload completion and pipeline result.

---

## Avoid

- Uploading through the Lambda/API Gateway — use the presigned URL directly to S3
- Using Fetch API for uploads where progress indication is needed — use `XMLHttpRequest`
- Processing more than 3 concurrent uploads — S3 may throttle, and the UX becomes confusing
- Requesting a presigned URL before validating the file — wastes an API call on invalid input
- Treating upload completion as pipeline completion — always poll the status endpoint
